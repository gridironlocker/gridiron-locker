# CRO & Conversion Audit — Gridiron Locker

**Date:** 2026-10-28 · **Scope:** homepage, collections, product pages, handoff to partner checkout, mobile UX, technical/SEO, tracking, trust · **Method:** live audit of the built site (617 pages), the full test/audit suite, rendered-markup inspection, and code review of the generators. Live partner checkouts (gridironlocker.shop / Viralstyle) are outside this sandbox's network — those items are marked **[needs admin access]** and separated from confirmed findings.

## 0. Architecture fact that reframes "cart & checkout"

This store deliberately has **no cart and no checkout of its own**. Every product card and every
`SHOP NOW` hands the shopper to the fulfilment partner's product page (Mayzing
`gridironlocker.shop` for 50 designs, Viralstyle for 46), where style/colour/size and payment
happen. Therefore:

- **"Add to Cart" on this site = the SHOP NOW click** (already instrumented with
  `shop_now_click` events per placement). Everything upstream must sell the *click*.
- **Checkout completion is a partner-side metric** [needs admin access]. No site-side fix can
  repair a partner payment gate; the site's job is to deliver *qualified, expectation-matched*
  clicks and to not lose anyone before the tap.

## 1. Executive summary

The storefront is structurally healthy: 0 broken links, 96/96 correct handoffs, 116/116 redirect
stubs, valid schema, 617 pages with unique metadata, and honest partner-scoped copy. The
conversion problem is not "broken buttons" — it is (a) **mobile delivery weight**, (b) **trust
opacity at the handoff moment**, (c) **measurement blindness**, and (d) **off-site factors**
(traffic quality, handoff-side experience, brand proof). This audit fixed (a) and part of (b) in
code today; (c) and (d) need operator access and are itemised below.

## 2. Confirmed findings (evidence attached)

### Critical

**C1 — IP/design-law exposure poisons trust and every paid channel.** `qa_deep`: 14 live products
use player names/numbers/photography and 5 hero banners show official team marks, against the
project's own `DESIGN-BLUEPRINT.md` §2. Beyond legal risk: it is what closes marketplace/ad
accounts (two Etsy accounts + Merch by Amazon are already gone), and an ad-review rejection caps
every paid growth lever in the 30-day plan. *Recommendation:* delist/noindex the 14 designs and
replace hero art — owner decision, unchanged from `SITE-AUDIT-2026-10-26.md`.

**C2 — the funnel is measurable in theory, blind in practice.** GA4 (`G-5RHGJSLZNG`) and the
Pinterest Tag only load after cookie-banner opt-in; `pinterest_tag_id` in `src/config.json` is
**empty** (the tag never loads at all); `data/seo/gsc_export.json` is empty (no query/CTR data);
no Meta Pixel exists anywhere. You cannot fix "visitors browse and leave" without knowing
browse→click rates per page. *Fix path:* create the Pinterest Tag and paste the ID (I wire the
config value); export GSC into `gsc_export.json`; decide on consent-mode vs. current opt-in for
GA4; Meta Pixel ID + `[needs admin access]` for Events Manager setup.

### High

**H1 — hero LCP weight (FIXED, §3).** Seven hero/feature images (2,378 KB total, 2048px wide,
371–431 KB each) were served as single-src JPEGs — a 375px phone downloaded the same file as a
desktop. This is the single biggest mobile speed cost on the store, and mobile is the primary
shopping device for fan traffic.

**H2 — font render-chain (FIXED, §3).** `style.css` line 1 `@import`ed Google Fonts, serialising
discovery: HTML → 132 KB stylesheet → fonts CSS → font files. The codebase's own comment says
fonts should load "with a `<link>` in `<head>`… never an `@import` in the shared stylesheet" —
the main typefaces violated that.

**H3 — returns opacity at the point of decision (FIXED, §3).** The buybox trust strip never
mentioned returns (the word appeared once site-wide, in the footer nav). The honest partner-scoped
facts live on `/shipping/`, two taps away from the BUY box. Now surfaced where the decision
happens.

**H4 — 7 creator pages advertise discount codes that may not exist in the partner cart**
(`AMBER`, `CRYSTAL`, `DESTINY`, `LAQUALA`, `VIP10`, `JOE10`, `ORTIZ` — "redeemable at checkout",
but checkout is on Mayzing/Viralstyle) **[needs admin access]**. If a code fails at checkout, the
visitor doesn't just leave — they leave *angry*. Verify each code in the partner cart or remove
the claim.

**H5 — the handoff is a brand cliff [needs admin access].** Confirmed from repo docs
(`MAYZING-STORE-THEME.md`): the dark premium storefront hands shoppers to a plain light catalogue
with different type/palette; the theme spec was written but is a Mayzing dashboard setting. Also
the second hop (`gridironlocker.shop`) is a different domain from the advertised
(`gridironlocker.store`) — the PDP states this honestly ("Checkout happens on Mayzing"), which
helps, but the theme mismatch is the remaining surprise. Fix in the Mayzing admin per the spec.

**H6 — 1,458 `<img>` tags (82 unique) hot-link signed Mayzing CDN URLs** (`buyer-experience-
gateway.mayzing.com/...sig:.../image.png`). If signatures expire, every product image breaks at
once; there is also no cache control and no responsive sizing (w:1000 PNG for a 530px slot).
Self-hosting needs network egress to the CDN **[needs admin access/runner]** — `dl.py` pattern
already exists for Viralstyle assets.

### Medium

- **M1 contact form:** FormSubmit `_captcha` disabled (spam/abuse surface) and the contact email
  is base64-"obfuscated" (trivially reversible) `[operator: enable captcha in FormSubmit]`.
- **M2 choice paralysis:** 7 near-duplicate design clusters (`cle-browns` ×3, `no-fly-zone` ×2,
  `1946 cleveland football` ×2, …) compete with each other in grids and search. Canonicalise one
  winner per cluster.
- **M3 slug quality** (frozen by contract): truncated/typo slugs (`lets-go-cle-copy`,
  `be-awar-of-dawg`) hurt shareability and click-trust; fix only with a redirect plan.
- **M4 thin/repeated copy:** 6 sentences repeat across 10–13 product pages each.
- **M5 `style.css` 132 KB unminified, render-blocking** (gzip on Pages mitigates to ~22 KB; a
  build-time minify step is the clean fix — deliberately deferred: regex-minifying a 132 KB
  stylesheet needs proper tooling).
- **M6 `/drops/` discards 3 queued designs** at build (stale `data/live_drops.json` entries).

## 3. Implemented fixes — before/after

## 5. Mobile UX assessment

**Good (verified):** 26 responsive breakpoints, zero fixed widths >360px, 2-up product grids,
sticky mobile CTA bar (`data-placement="sticky_bar"`), width/height on every image (no layout
shift), lazy-loading below the fold, `fetchpriority=high` limited to 5 elements, tap-friendly
buttons, working mobile menu, quick-view modal with `role="dialog"`.

**Was broken (fixed):** hero weight on cellular (−78%), font render chain.

**Remaining mobile risks:** CDN card images are w:1000 PNGs (heavy even lazy); `style.css` still
blocks first paint; no offline/app-shell behaviour. Recommend: card-image width negotiation with
Mayzing or self-hosting (H6), CSS minification (M5).

## 7. Conversion path — what to improve next (beyond this pass)

1. **Qualify the click, keep expectations matched** (done partially): price + partner + returns
   now sit in the buybox. The remaining killer is H5 — the destination must *look* like the
   promise.
2. **Build proof where it's real:** import partner-side order reviews if Mayzing exposes them
   `[needs admin access]`; creator locker content (real people wearing real product) is the
   authentic substitute until then. Never fabricate — the repo's tests enforce this and so does
   FTC/EU law.
3. **Recover the non-buyer:** the site captures nothing (no email/consent list of its own). One
   "new drops" email field (footer, optional) is the only structural change worth unfreezing the
   content rules for — propose, don't apply.
4. **Kill the duplicates (M2)** — fewer, better choices convert.

## 8. 30-day conversion improvement plan

**Week 1 — measurement truth (operator, ~3 hours):** Pinterest Tag ID → config; GSC export →
`data/seo/gsc_export.json`; quantify GA4 consent rate; test the 7 discount codes; run 3 mobile
test purchases on Mayzing + 2 on Viralstyle and record every friction point.

**Week 2 — handoff experience:** apply `MAYZING-STORE-THEME.md` in Mayzing admin (H5); fix/remove
dead promo codes (H4); confirm CDN signature policy (H6) and schedule self-hosting if needed.

**Week 3 — demand + proof:** creator locker game-day posts (trade deadline Nov 4), first paid
micro-tests (Spark Ads on proven organic, $20–50/day), 10 micro-creator seeds (product-for-post).

**Week 4 — learn + prune:** read `shop_now_click` CTR per placement and per collection; retire the
weakest duplicate cluster (M2); A/B the buybox copy order (price-first vs design-first); plan
email capture if the pattern is "browse many, click few".
